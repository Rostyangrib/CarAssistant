2. Цель этого этапа

Добавить локальный голосовой ввод Speech-to-Text.

Пользователь должен иметь возможность произнести команду в микрофон, после чего приложение:

1. записывает речь;
2. локально преобразует её в текст;
3. показывает распознанный текст;
4. передаёт этот текст в существующий Assistant Core;
5. выполняет команду через уже существующий CommandRouter / gemma4:e2b / MCP / MusicService;
6. выводит текстовый ответ ассистента.

Итоговая цепочка должна выглядеть так:

Микрофон
    ↓
AudioRecorder
    ↓
Local STT
    ↓
Распознанный текст
    ↓
CommandRouter
    ├── Direct → MusicService
    │
    └── gemma4:e2b → MCP → MusicService
                              ↓
                           Player
    ↓
Текстовый ответ ассистента

Очень важно:

STT является только новым способом получить текст пользователя.

После распознавания голосовая команда должна идти в тот же метод обработки, что и команда, введённая с клавиатуры.

Не создавай отдельную бизнес-логику для голосовых команд.

3. Границы этапа

На этом этапе реализуется только:

• захват звука с микрофона;
• определение конца голосовой фразы;
• локальное распознавание русской речи;
• передача распознанного текста в существующий Assistant;
• понятные ошибки;
• измерение задержки;
• тесты;
• документация.

На этом этапе НЕ реализовывать:

• Wake Word;
• постоянное фоновое прослушивание;
• TTS;
• голосовой ответ;
• подавление музыки во время обращения к ассистенту;
• эхоподавление автомобильной аудиосистемы;
• diarization;
• идентификацию пользователя по голосу;
• cloud STT;
• отправку аудио во внешние сервисы;
• Raspberry Pi;
• GUI;
• web interface;
• новые музыкальные возможности;
• persistent memory;
• RAG;
• multi-agent architecture.

Ассистент пока отвечает текстом в терминале.

4. Сценарий использования без Wake Word

Wake Word будет реализован отдельным этапом позже.

Поэтому сейчас используй простой и предсказуемый режим push-to-talk:

1. пользователь запускает приложение с флагом --voice;
2. приложение предлагает нажать Enter для начала записи;
3. пользователь нажимает Enter и произносит одну команду;
4. запись автоматически завершается после того, как речь началась и затем наступила заданная пауза;
5. распознанный текст передаётся в существующий Assistant;
6. после ответа приложение снова готово принять следующую голосовую команду.

Пример:

python -m app.main --voice

Car AI Assistant started in voice mode.

Нажмите Enter и произнесите команду. Для выхода нажмите Ctrl+C.

Listening...

You said: Включи Кино

Assistant: Включаю «Группа крови» — Кино.

Не имитируй Wake Word с помощью бесконечного распознавания всех звуков вокруг.

Если выбранная библиотека захвата звука не позволяет удобно запускать и завершать запись одним Enter, допустим близкий по смыслу интерфейс. Но он должен быть простым, явным и не требовать постоянного фонового прослушивания.

5. STT engine

Используй локальный faster-whisper как основной STT engine.

Базовая модель этапа:

faster-whisper-small, multilingual

Ориентируйся на ноутбук:

• Windows;
• Python 3.12+;
• 16 GB RAM;
• выполнение на CPU должно поддерживаться;
• интернет не должен требоваться во время обычной работы ассистента.

Настройки по умолчанию:

• language = ru;
• device = cpu;
• compute_type = int8;
• beam_size — небольшое значение, подходящее для низкой задержки;
• vad_filter можно использовать внутри faster-whisper, если это действительно помогает и не заменяет корректное завершение записи.

Не используй английскую модель Whisper: нужна multilingual-модель с поддержкой русского языка.

Не подключай облачные API Google, Yandex, OpenAI или другие внешние STT-сервисы.

Не скачивай модель автоматически при обычном запуске приложения.

Модель должна устанавливаться пользователем отдельно и храниться локально. В README покажи точный способ загрузки, соответствующий выбранной реализации. При запуске STT используй локальные файлы и запрети незаметную сетевую загрузку.

Если модели нет, покажи понятное сообщение с инструкцией установки, а не длинный traceback.

6. Архитектура STT

Не помещай запись микрофона и Whisper в CLI, Assistant, CommandRouter или MusicService одним большим блоком.

Добавь небольшие заменяемые компоненты. Например:

stt/
├── __init__.py
├── base.py
├── faster_whisper.py
├── recorder.py
└── models.py

interface/
└── voice.py

Или адаптируй эту структуру к реальному проекту.

Минимальные ответственности:

AudioRecorder

• получает аудио с выбранного микрофона;
• приводит его к формату, подходящему для STT;
• завершает запись после тишины;
• ограничивает максимальную продолжительность записи;
• не знает про LLM, MCP и музыку.

SpeechToText

• принимает аудиоданные или путь к тестовому WAV;
• возвращает распознанный текст и доступные метаданные;
• не знает про Assistant, MusicService и CLI.

VoiceInterface

• управляет циклом пользовательского взаимодействия;
• вызывает AudioRecorder;
• вызывает SpeechToText;
• передаёт полученный текст в тот же Assistant.handle(...), который использует CLI;
• выводит распознанную фразу и текстовый ответ.

Не создавай вторую версию Assistant специально для голоса.

7. Абстракции

Предусмотри простые интерфейсы, чтобы позже можно было заменить реализацию без изменения core.

Например:

class SpeechToText(ABC):
    def transcribe(self, audio: AudioData) -> Transcription:
        ...

class AudioRecorder(ABC):
    def record_utterance(self) -> AudioData:
        ...

Transcription может содержать:

• text;
• detected_language, если backend действительно возвращает язык;
• audio_duration;
• speech_duration или другие реально доступные показатели.

Не придумывай confidence, если faster-whisper не даёт корректного итогового confidence без спорной собственной формулы.

Не переусложняй абстракции. Для текущего этапа достаточно одной рабочей реализации recorder и одной рабочей реализации STT плюс fake/mock для тестов.

8. Формат аудио

Для STT используй единый внутренний формат:

• mono;
• 16 kHz;
• PCM или float32, подходящий выбранному API faster-whisper.

Если микрофон работает с другой частотой, корректно преобразуй звук либо запроси у устройства 16 kHz, если оно это поддерживает.

Не сохраняй каждую голосовую команду на диск без необходимости.

Предпочтительно передавать аудиомассив напрямую в STT.

Если для совместимости нужен временный WAV:

• создавай его безопасно во временном каталоге;
• гарантированно удаляй после распознавания;
• не добавляй запись в репозиторий;
• не оставляй пользовательскую речь в data или logs.


⸻


9. Захват речи и определение тишины

Для микрофона выбери небольшую кроссплатформенную Python-библиотеку, которая стабильно работает на Windows. Предпочтительный вариант — sounddevice, если он совместим с текущим окружением.

Запись должна:

1. ожидать начала речи;
2. не завершаться до того, как речь реально началась;
3. завершаться после настраиваемого периода тишины после речи;
4. иметь максимальную длительность, чтобы никогда не записывать бесконечно;
5. корректно обрабатываться при Ctrl+C;
6. не падать, если микрофон отсутствует или занят.

Для этого этапа допустим простой детектор тишины по энергии/RMS. Не добавляй тяжёлую DSP-систему.

Порог тишины должен быть настраиваемым.

Учти тихие микрофоны и фоновый шум. Если добавляешь короткую калибровку фонового шума перед фразой, она должна быть быстрой, понятной пользователю и не усложнять обычный запуск.

Ограничения по умолчанию должны быть разумными, например:

• ожидание начала речи — ограниченное по времени;
• тишина после речи — около 1 секунды;
• максимальная фраза — около 15 секунд.

Точные значения выбери после проверки и вынеси в конфигурацию.

Расширь существующий Settings и .env.example.

Минимально предусмотри настройки примерно такого смысла:

• пустой AUDIO_INPUT_DEVICE означает системный микрофон по умолчанию;
• путь модели должен корректно разрешаться относительно корня проекта;
• существующие настройки Stage 1 и Stage 2 должны сохраниться.

11. Режимы запуска

Существующий текстовый режим должен остаться режимом по умолчанию:

python -m app.main

Новый голосовой режим:

python -m app.main --voice

Также добавь полезный диагностический режим:

python -m app.main --list-audio-devices

Он должен вывести доступные устройства ввода и завершить работу без запуска Ollama и загрузки STT-модели.

Добавь возможность выбрать микрофон через конфигурацию. Если это хорошо вписывается в существующий argparse, можно также поддержать явный аргумент командной строки для устройства.

Для воспроизводимой ручной проверки желательно добавить режим транскрибации WAV-файла, например:

python -m app.main --transcribe-file path\to\command.wav

Этот режим должен распознать файл, показать текст и завершиться. Он не обязан выполнять музыкальную команду. Не добавляй его, если он заметно усложняет CLI, но оставь эквивалентный простой способ проверить STT без живого микрофона.

Сохрани совместимость с:

• --mock;
• --debug;
• --scan.

Не создавай противоречивые комбинации флагов. Для несовместимых режимов argparse должен показывать понятную ошибку.

Флаг --mock по-прежнему заменяет LLM, а не STT. Unit-тесты STT должны использовать отдельные fake-компоненты через dependency injection.

12. Инициализация по требованию

Не загружай faster-whisper и его модель в обычном текстовом режиме.

Не открывай микрофон при:

• обычном python -m app.main;
• --scan;
• --list-audio-devices;
• запуске unit-тестов, которым микрофон не нужен.

Тяжёлые STT-зависимости и модель должны инициализироваться только в голосовом режиме или при явной транскрибации файла.

Это важно для скорости запуска текстового режима и изоляции ошибок.

13. Обработка результата распознавания

После STT обязательно нормализуй только технические детали:

• убери пробелы по краям;
• корректно обработай пустой результат;
• не переписывай смысл фразы собственными regex;
• не исправляй вручную названия исполнителей большим словарём;
• не дублируй NLP, который уже выполняют CommandRouter и gemma4:e2b.

Пример:

Микрофон:
«поставь на паузу»

STT:
"Поставь на паузу"

Assistant.handle("Поставь на паузу")

CommandRouter:
DIRECT

MusicService.pause()

Другой пример:

Микрофон:
«давай что-нибудь из кино»

STT:
"Давай что-нибудь из Кино"

Assistant.handle(...)

CommandRouter:
LLM

gemma4:e2b → MCP → MusicService

STT не должна сама выбирать музыкальный tool.

14. Пустая речь и ошибки распознавания

Если пользователь ничего не сказал или речь не распознана:

Не удалось распознать речь. Попробуйте ещё раз.

После этого приложение не должно вызывать Assistant, gemma4:e2b или MCP с пустой строкой.

Если запись не началась за время ожидания:

Речь не обнаружена.

Если микрофон отсутствует:

Микрофон не найден. Проверьте устройство ввода.

Если устройство занято или недоступно:

Не удалось открыть микрофон. Проверьте настройки устройства ввода.

Если локальная STT-модель отсутствует:

Локальная модель распознавания речи не найдена.
Покажи точную команду или шаг установки из README.

Если backend не может загрузиться:

Не удалось запустить локальное распознавание речи.

Технические детали сохраняй в debug-логах, но обычному пользователю не показывай большой traceback.

После обычной ошибки одной фразы голосовой цикл по возможности должен продолжить работу.

15. Производительность

Для автомобильного ассистента задержка важна.

Измеряй минимум:

• audio_duration;
• speech_wait_latency;
• stt_latency;
• assistant_latency;

Не смешивай длительность самой произнесённой фразы со временем вычисления STT.

[DEBUG] compute_type=int8
[DEBUG] transcription="Следующий трек"
[DEBUG] stt_latency=0.83s
[DEBUG] route=direct
[DEBUG] assistant_latency=0.01s
[DEBUG] total_voice_request_latency=3.31s

Не обещай конкретную скорость до измерения на реальном ноутбуке.

16. Debug и логирование

Сохрани существующий --debug.

В debug-режиме логируй:

• выбранное устройство ввода;
• фактическую sample rate;
• начало и конец записи;
• причину завершения записи: silence / timeout / cancel;
• длительность аудио;
• имя и настройки STT-модели;
• распознанный текст;
• STT latency;
• существующую информацию Router / LLM / Tool / Timing.

Не логируй:

• сырые аудиобайты;
• полные numpy-массивы;
• скрытые рассуждения gemma4:e2b;
• секреты и переменные окружения целиком.

В обычном режиме показывай только понятный пользовательский диалог.

17. Приватность

Голосовой ввод должен работать локально.

Требования:

• не отправлять аудио в интернет;
• не отправлять транскрипции во внешние STT-сервисы;
• не сохранять записи постоянно;
• не включать микрофон в текстовом режиме;
• явно показывать пользователю состояние Listening...;
• прекращать запись после завершения фразы или таймаута;
• корректно освобождать аудиоустройство после каждой записи и при выходе.

Обычная работа gemma4:e2b через локальный Ollama остаётся без изменений.

18. Зависимости

Добавляй только действительно необходимые зависимости.

Предполагаемый минимум для этого этапа:

• faster-whisper;
• sounddevice;
• numpy, если она не устанавливается транзитивно или нужна явно.

Закрепи совместимые диапазоны версий в pyproject.toml и requirements.txt в стиле существующего проекта.

Не добавляй PyTorch, если faster-whisper работает через CTranslate2 без него.

Не добавляй FFmpeg как обязательную внешнюю программу, если выбранный путь с массивом аудио или WAV позволяет обойтись без неё. Если FFmpeg всё же реально требуется выбранной реализацией, честно задокументируй установку и причину.

Не добавляй Docker.

19. Тестируемость

Unit-тесты не должны:

• требовать реальный микрофон;
• записывать звук пользователя;
• скачивать модель;
• загружать настоящую Whisper-модель;
• требовать запущенный Ollama;
• зависеть от наличия аудиоустройства в CI.

Используй dependency injection и fake/mock реализации.

При необходимости добавь маленький тестовый WAV fixture с короткой синтетической тишиной/сигналом. Не добавляй в репозиторий реальные записи голоса пользователя.


⸻


20. Тесты AudioRecorder

Минимально проверь:

• аудио имеет ожидаемые channels и sample rate;
• запись не завершается до начала речи;
• запись завершается после периода тишины после речи;
• срабатывает speech timeout;
• срабатывает максимальная длительность;
• ошибка устройства преобразуется в понятное доменное исключение;
• ресурсы освобождаются после ошибки и отмены.

Алгоритм тишины тестируй на заранее сформированных массивах аудиофреймов, а не через настоящий микрофон.


⸻


21. Тесты STT adapter

Минимально проверь:

• успешное преобразование результата backend в Transcription;
• передаётся русский язык;

22. Тесты VoiceInterface

Минимально проверь:
